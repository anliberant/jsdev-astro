AI coding agents can write a component in seconds. Getting them to follow your team’s conventions, check their work, or stop overengineering is a different problem. That is where agent skills come in.

A skill is usually a set of instructions and supporting resources that tells an agent how to approach a particular job. Some help with code reviews. Others focus on design, documentation, database queries, or planning. They do not make a model infallible, but they can make its workflow more consistent.

This list revisits 30 skills from a larger community roundup, with repository links and updated star estimates. It is **not a ranking of individual skill downloads**: GitHub awards stars to repositories, not to the skills inside them. When several skills share a repository, they naturally share the same star count. Counts are rounded, source-dependent snapshots, not live GitHub API readings. The obra/superpowers figure is supported by a third-party snapshot of 304K stars on October 23, 2026; other repository figures remain provisional and require a fresh GitHub API audit before publication.

## Installing a skill

For repositories compatible with the open Skills CLI, start with:

```bash
npx skills add owner/repository --skill skill-name
```

To see what a repository offers before installing:

```bash
npx skills add owner/repository --list
```

Check the repository documentation first. Some projects use their own installers or plugin systems, and a GitHub project is not necessarily itself an installable skill. Read the `SKILL.md` and any scripts before granting an agent access to your files, shell, browser, or credentials.

## Which skills should you try first?

If you build web apps, start with `vercel-react-best-practices`, `web-design-guidelines`, and `frontend-design`. They address different parts of the same job: performance, usability, and visual implementation.

For larger codebases, `research`, `to-spec`, `code-review`, and `verification-before-completion` are a useful sequence. Give the agent context before asking it to change files, then demand evidence that the change works.

For debugging, choose `systematic-debugging` or `diagnosing-bugs` rather than piling on speculative fixes. And if your agent keeps inventing abstractions, `ponytail` is worth a look.

## A note on popularity

Stars measure attention to the **whole repository**, not the quality or popularity of a particular skill. A repository with 15 skills can rank above a focused single-skill project without any of those 15 being more widely installed. Also, several projects here are broader tools or libraries, so their installation paths may differ from a standard `SKILL.md` package.

The useful question is not which skill has the largest number beside it. It is whether the instructions match your workflow, whether the project is maintained, and whether you can inspect what the agent will actually do.

## Final thoughts

A good skill should reduce guesswork, not add ceremony. Pick one repetitive task you already do, try the relevant skill on a small branch or sample project, and compare the result with your normal process. If it saves review time without hiding important decisions, keep it. Otherwise, move on.
